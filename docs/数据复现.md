## 3. 数据整理

```powershell
.venv\Scripts\python.exe scripts\organize_plantvillage.py
```

该脚本做四件事（**幂等，可中断续跑**）：

1. 解压 zip；
2. 排除 `Background_without_leaves` 类别（不属于病害分类任务）；
3. **类别名归一化**——源压缩包用 Kaggle 命名，需映射到 PlantVillage 命名：

   | 源命名 | 归一化为 |
   |---|---|
   | `Cherry___` | `Cherry_(including_sour)___` |
   | `Corn___` | `Corn_(maize)___` |
   | `Corn___Common_rust` | `Corn_(maize)___Common_rust_`（注意末尾下划线） |

4. 增强版划入 `train/`、原始版划入 `val/`。

**历史踩坑**：早期版本用 `shutil.rmtree` 清空目标目录，在本机开发环境中会被删除守卫拦截
（批量删除约 3.8 万张图片时触发）。现版本改为**幂等不清空**，重复运行只补缺失文件。

**耗时预期**：本机磁盘 IO 较慢（实测约 1450 张/分钟），完整解压整理约 6 万张需约 1 小时。
请预留时间，不要中途打断。

## 4. 训练

```powershell
# 前置：确认 CUDA 可用
.venv\Scripts\python.exe -c "import torch;print(torch.__version__, torch.cuda.is_available())"

# 训练（v2 参数）
.venv\Scripts\python.exe scripts\train_v2.py --data data/plantvillage ^
    --model-size n --imgsz 224 --epochs 30 --strong-aug --device 0 --batch 32
```

产物输出到 `runs/agriguard_v2/`。训练完成后把 `weights/best.pt` 复制到 `models/best.pt`
（旧版本可用 `scripts/finalize_train.py` 自动完成）。

### 关键参数与踩坑（务必保留）

| 项 | 值 / 说明 |
|---|---|
| 优化器 | **必须显式指定 `SGD`**。`optimizer=auto` 会选 MuSGD，与 torch 2.13 存在 view 兼容性 bug（`RuntimeError: view size is not compatible...`），第一个 epoch 即崩。`train_v2.py` 已固定为 SGD。 |
| 不启用 `--balance` | 数据已较均衡，类别平衡只是复制文件、浪费时间。 |
| AMP 检查 | 会尝试下载 `yolo26n.pt`（部分网络环境被拦），跳过不影响训练，`amp=True` 仍生效。 |
| 硬件参考 | 约 19.5 it/s，每 epoch 约 77 秒，30 epoch 约 40–50 分钟。 |
| 训练收尾 | 写 `val_batch0_pred.jpg` 时可能因权限被拦，**非致命，训练本身成功**。 |

### 已达成指标

| 指标 | 值 |
|---|---|
| epoch | 30 / 30 |
| 训练总时长 | 约 0.69 小时 |
| top1 准确率 | **0.99743** |
| top5 准确率 | 0.99992 |
| val/loss | 0.00912 |

逐 epoch 记录见 `runs/agriguard_v2/results.csv`（30 行连续无缺），
训练曲线 `results.png`，混淆矩阵 `confusion_matrix_normalized.png`。

**混淆矩阵实测为一条干净的对角线**，38 类可分 —— 这是「模型未退化为只会输出单一类别」的直接证据
（项目早期曾出现过 32 张图中 68.8% 被判为同一类的坍缩现象）。

## 6. 换模型后必须重新标定（重要）

任何**基于特征空间的阈值都与模型权重强绑定**。本项目有两处：

1. `backend/app/constants.py` 的 `OOD_REJECT_THRESHOLD` / `OOD_WARN_THRESHOLD`（当前 0.25 / 0.32）；
2. `scripts/verify_pipeline.py` 的合成图夹具与断言。

**历史上已经发生过一次失效**：这两个阈值是按首轮模型标定的，2026-09-15 重训 v2 后
特征空间改变（整条 OOD 分布下移约 0.05–0.06，自带合规示例图从约 0.43 变为 0.3691），
但阈值与回归夹具都未同步，导致回归测试**长期静默失败**（一直 4/5 却无人察觉）。

因此：**重训模型后，必须重跑 `verify_pipeline.py`，并按实测值同步更新夹具与
`constants.py` 的标定注释。** 具体做法见该脚本模块 docstring 与 constants 对应注释。
