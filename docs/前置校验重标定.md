# 前置校验重标定记录

> 日期：2026-09-20 · 影响文件：`backend/app/precheck.py`、`tests/test_baseline.py`、`scripts/verify_pipeline.py`
> 起因：建立测试素材库时，发现**产品会拒绝它自己最擅长的那类输入**

---

## 一、问题（实测，严重）

建立测试素材库时，把 PlantVillage **验证集自己的样本**（模型训练分布的同源数据）
送进 `/predict`，结果**绝大多数被"拍摄规范"前置校验拦下，根本没进入模型**：

| 指标 | 修复前 |
|---|---|
| 验证集抽样 228 张的前置校验通过率 | **20.2%** |
| 被拒原因 | 几乎全部是「背景不是纯色」 |
| 这些样本模型的实际召回 | 0.9967（模型完全认得） |

**也就是说：模型对这批图的识别几乎全对，但产品在门口就把它们拦掉了。**

### 根因

`_background_uniformity()` 把图像**四边各 8% 的边缘带整块**当作背景样本来统计：

```python
# 修复前
bg = concatenate([top_band, bottom_band, left_band, right_band])
std = bg.std(axis=0).mean()          # 基准用「均值」
dominant = mean(distances <= 45)     # 主色占比
```

但**叶片经常伸到画面边缘**。叶片像素混进采样带后：
- 边缘带里同时存在"灰色背景"与"绿色叶片"两类像素 → 标准差被拉高（实测中位数 33.4，远超阈值 25）；
- 主色基准用**均值**，被叶片颜色拉偏 → 主色占比虚低（中位数仅 0.55，远低于要求的 0.85）。

两项都不过 → 判为"背景不纯" → 拒绝。

**这个缺陷长期未被发现的原因**：项目自带的"合规示例图"
（`frontend/_demo_leaf_compliant.jpg`）是**专门为通过这套校验而制作的**
（仓库里有 `scripts/make_demo_compliant.py`）。用它演示永远通过，
于是校验逻辑本身是否合理从未被真正检验过。

---

## 二、修复

### 2.1 只在「真背景像素」上评估背景

先用已有的绿色前景掩膜抠出叶片并排除，只对剩余的边缘带像素做统计；
基准从**均值**改为**中位数**（对残留的少量叶缘/病斑像素更稳健）。

```python
fg = leaf_foreground_mask(img) > 0      # 叶片前景（内部已做凸包填充与膨胀）
sel = band & (~fg)                      # 边缘带里的真背景像素
std, dominant = 统计(img[sel])           # 基准用中位数
```

若真背景像素不足 200 个（叶片几乎占满画面）→ **无法判断 → 放行**。
因为"叶片占满画面"本身就是合规拍摄，不应拦截。

### 2.2 阈值按新口径重标定

| 参数 | 修复前 | 修复后 | 依据 |
|---|---|---|---|
| `BACKGROUND_MAX_STD` | 25.0 | **45.0** | 新口径下验证集 std 中位数 24.9 / p90 40.2 |
| `BACKGROUND_MAX_STD_LOOSE` | 55.0 | **80.0** | p95 49.1、max 75.9，取 80 覆盖全部同源样本 |
| `BACKGROUND_MAX_DISTANCE` | 45.0 | **70.0** | 配合中位数基准 |
| `BACKGROUND_DOMINANT_RATIO` | 0.85 | **0.50** | 新口径下验证集 p10 为 0.729、min 0.428 |
| 主色基准 | 均值 | **中位数** | 抗叶片像素污染 |

### 2.3 架构分工明确化

修复过程也厘清了两个质量闸门的分工：

| 闸门 | 职责 | 依据 |
|---|---|---|
| **前置校验**（图像统计） | **弱校验**：① 图可读 ② 尺寸够 ③ 有叶片 ④ 背景不是明显杂乱 | 纯图像统计，同分布样本上不应误杀 |
| **OOD 拒识**（模型侧） | **主力质量闸门**：判断"这张图是否属于模型能可靠处理的范围" | 已标定；同分布验证集实测 **0% 误拒（0/304）**，比图像统计可靠得多 |

## 三、修复效果（实测）

### 3.1 通过率

| 指标 | 修复前 | 修复后 |
|---|---|---|
| PlantVillage 验证集前置校验通过率 | 20.2% | **99.2%**（238/240） |
| 仍被拒的 2 张 | — | 原因是「未检测到叶片」（绿色像素 < 8%，属合理拒绝） |

### 3.2 明显不合法的输入仍然被拦（关键：不能为了放行而失去把关能力）

| 输入 | 结果 | 拦在哪一环 |
|---|---|---|
| 纯灰块 / 蓝色圆 / 文字卡片 | 拒绝 | 前置校验（未检测到叶片） |
| 叶片过小 / 全白 / 灰度叶片 / 32×32 | 拒绝 | 前置校验（未检测到叶片 / 尺寸过小） |
| 随机噪声 | **拒绝（ood=0.1352）** | **OOD 干脆拒识** |
| 多叶重叠 | **拒绝（ood=0.2225）** | OOD 拒识 |
| 合成纹理背景 + 绿椭圆 | **接受，但带警告（ood=0.2531，落在警告区）** | 见下方已知局限 |
| 极端宽高比（900×120） | 接受，识别为「玉米 · 健康」 | 误判但未崩溃，可接受 |

### 3.3 回归测试

`tests/test_baseline.py` 由 12 项扩到 **14 项，全部通过**。新增两条：

- `test_non_leaf_rejected`：非叶片必须被拒（核心不变式）
- `test_random_noise_rejected`：随机噪声必须被拒（质量闸门有效性）
- `test_precheck_accepts_training_distribution`：**防回归**——抽样 60 张验证集，
  要求前置校验通过率 ≥ 90%。这条用例专门守住本次修复，防止有人再把阈值收紧回去。

## 四、已知局限（如实记录）

1. **合成"纹理背景 + 绿椭圆"现在会被接受**（ood=0.2531，落在警告区）。
   这类图是绿色椭圆叠在随机噪声上，与实际布料/田间背景的统计特征不同。
   当前行为是"接受但明确提示结果仅供参考"——考虑到它并非真实场景，
   且 OOD 已给出警告，暂不额外加规则。**若后续采集到真实杂乱背景样张且被误接受，
   再考虑在前置校验中增加纹理（局部方差/边缘密度）判据。**
2. **`frontend/_demo_leaf.jpg`（早期的纹理背景示例图）现在会被接受**
   （ood=0.4676，识别为番茄·早疫病）。这是阈值放宽的直接结果，属预期变化。
   该图已不再作为"应被拒绝"的测试用例。
3. 本次未改动 OOD 阈值——它经复核与当前模型匹配良好（同分布零误拒），
   且真实非支持作物叶片（银杏）仍能稳定触发拒识（0.2219）。

## 五、对答辩的意义

这个缺陷本身就是一个**很好的故事**：

> "我们在做测试素材库时，发现系统会拒绝 PlantVillage 验证集自己 80% 的样本——
> 也就是说产品会拒绝它最擅长的输入。根因是背景判据把叶片伸到画面边缘的像素
> 也算进了背景统计。修正为'只在真背景像素上评估'后，通过率从 20% 升到 99%，
> 同时随机噪声、非叶片等非法输入仍全部被拦。"

它同时印证了**为什么 OOD 拒识才是主力质量闸门**：
纯图像统计很容易被拍摄方式的自然变化欺骗，而模型侧的分布外判据
在同分布数据上零误拒、在真异常输入上果断拒识。
