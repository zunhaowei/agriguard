## 0. 设计前提（先锁定，再动手）

### 0.1 设计寄存器与平台轴

| 判定项 | 结论 | 依据 |
|---|---|---|
| 设计寄存器 | **产品型（Product Register）** | 五页全部是「工具 UI / 数据界面」，设计服务于任务，不服务于品牌表达 |
| 平台轴 | **web（响应式）**，移动端 <768px 为第一公民 | Spec §7「≥1024 三栏/两栏，768–1023 两栏，<768 单栏」 |
| 设计风格基调 | **延续既有「田间仪器」语言**：白底、细线、大留白、结论先行 | `styles.css` 文件头自述；本次**不重做**风格 |
| 行业语境 | 农业 / 基层农技 | 品牌色已锁定 `--accent: #2E7D4F`（叶绿）+ `--teal`（虹膜青），**不得引入第二套色系** |

**产品型寄存器的三条硬性后果**（本规格全程遵守）：

1. **色彩克制**：中性色占 70–90%，强调色 `--accent` 占 5–10%，**每屏可见强调色使用 ≤2 处**。
2. **排版克制**：仅用系统既定字体栈（Inter / PingFang SC / HarmonyOS Sans SC / Microsoft YaHei），**不引入衬线展示体**；字重仅 400 / 500 两档（既有 Token 约定）。
3. **图片策略**：以「例图 / 缩略图 / 图标 / 数据」替代装饰性摄影；**不做抽象 3D 图形**。

### 0.2 三轴设计刻度

| 刻度 | 取值 | 说明 | 对本次的具体约束 |
|---|---|---|---|
| `DESIGN_VARIANCE` | **4**（偏移） | 产品型工具不宜艺术化，但拒绝完全对称的居中模板 | 病例库用「左栏 + 非等宽网格」的非对称双栏；登录页用「文案侧 + 表单侧」分屏（**禁止**居中 Logo + 欢迎语 + 单按钮的通用 Hero）；移动端全部回退单列 |
| `MOTION_INTENSITY` | **3**（克制） | 功能性动效为主 | 仅 hover / focus / 弹层进入 / 骨架微光；时长 140–280ms；**无装饰性循环动画**（语音按钮播放中的脉冲是唯一的「状态指示型」常驻动画，因其传达"正在播放"的语义） |
| `VISUAL_DENSITY` | **5**（日常应用） | 标准间距 | 卡片网格 gap `--space-4`；列表行 padding `--space-3 --space-4`；节区间距按 `--space-6`/`--space-7` |

### 0.3 明确不做（反向约束）

- 不做「千篇一律 Hero」：**首屏直接给真实内容**（作物分类、病害卡片、诊断记录），不放"大标题 + 副标题 + 居中 CTA"。
- 不做「首屏指标模板」（大数字 + 小标签 + 辅助数据）。
- 不做卡片左侧彩色条纹（`border-left > 1px` 强调）；卡片强调只用**边框色变化**。
- 不做渐变文字、不做装饰性毛玻璃、不做 `border + blur ≥16px` 的幽灵卡片。
- 不使用编号 section 标记（`01 · 关于` 这类 AI 脚手架语法）。
- 不使用 emoji（含文档标题）；不硬编码颜色；不使用弹跳缓动。

### 0.4 常量与真源

- **作物清单 / OOD 阈值 / 上传上限**：一律来自 `GET /api/v1/meta`，前端**不得硬编码**（Spec §3 已知坑 + 工作交接 §4.3）。
- **页面文案**：全部中文、面向农户口语（见 §4 文案总表）。
- **空/错误/加载态**：每个「有数据渲染」的区块都必须同时设计三态（见 §5 状态矩阵）。

## 1. 全局约定

### 1.1 容器与栅格

| 用途 | 类名 | 宽度 | 备注 |
|---|---|---|---|
| 原诊断页（index） | `.app` | `min(760px, 100%)` | 沿用既有，**不改** |
| 病例库 / 病例详情 / 历史 | `.app.app--wide` | `min(var(--app-wide), 100%)` = `min(1120px,100%)` | 新增 Token `--app-wide` |
| 登录页 | `.app` | `min(760px, 100%)` | 登录表单本身控制在 420px 内，避免宽屏拉长输入框 |

栅格策略：

- ≥1024px：**12 列心智栅格**。病例库 `[作物列表 var(--case-side)] [1fr]`；卡片网格 `repeat(auto-fill, minmax(220px, 1fr))`（1120 宽下自然成 3 列）。
- 768–1023px：**两栏**。病例库 `[200px] [1fr]`，卡片网格 `minmax(200px, 1fr)`（自然成 2 列）。
- <768px：**单栏**。作物列表降级为横向可滑 chip 行；卡片网格 1 列。

### 1.2 断点

| 断点 | 生效范围 | 关键变化 |
|---|---|---|
| `≥1024px` | 桌面 | 完整双栏 / 三列卡片 / 顶部导航链接全展开 |
| `768–1023px` | 平板 | 收窄双栏 / 两列卡片 / 导航链接仍展开 |
| `<768px` | 手机 | 单栏 / 顶部导航链接收起为**底部标签栏** / 弹层变底部抽屉 |

> 既有 `styles.css` 的 `@media (max-width: 600px)` 段保留不动，作为单栏内部的细节微调。

### 1.3 触控与键盘

- 所有可点元素**最小 44×44px**（`min-height: var(--space-8)` = 44px）；行内纯图标按钮用 `.btn-icon`（44×44 视觉方形）。
- 全站 Tab 可到达；焦点样式沿用既有 `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`，**不新增、不移除**。
- 弹层：打开时焦点移入弹层首个可聚焦元素（`.dialog-close`），关闭时焦点归还触发元素；`ESC` 关闭；Tab 在弹层内循环（focus trap）。

### 1.4 动效

| 场景 | 取值 | 说明 |
|---|---|---|
| hover / 状态确认 | `var(--dur-fast)` 140ms | 颜色、边框变化 |
| 卡片抬升 / 列表行强调 | `var(--dur)` 200ms | `translateY(-2px)` + `--elev-2` |
| 弹层 / 轻提示进入 | `var(--dur-slow)` 280ms | 淡入 + 8px 上移，**无弹跳** |
| 骨架屏微光 | 1.4s 循环 | 唯一允许的循环动画之一 |

`prefers-reduced-motion: reduce` 时全局规则已将动效压至 0.01ms；骨架屏额外静止为 `opacity: 0.7`。

### 1.5 图标系统（新增清单）

**统一规格（沿用项目既有约定，不得偏离）**：`viewBox="0 0 24 24"`、`fill="none"`、`stroke="currentColor"`、`stroke-width="2"`、`stroke-linecap="round"`、`stroke-linejoin="round"`；**尺寸仅 16 / 20 / 24px**；无 emoji。

## 2. 页面级规格

### 2.1 `login.html` — 登录 / 注册

- **路由**：`/static/login.html`
- **作用**：账号入口。未登录访问受保护页（history）时被引导至此。
- **依赖 API**：`POST /api/v1/auth/login`、`POST /api/v1/auth/register`、`GET /api/v1/auth/me`（自动续期校验）

**信息架构（区块顺序）**

```
[顶部导航 .site-nav]  品牌 | 主导航 | 认证区（未登录时此页认证区只留"返回诊断"） 
[.auth-layout  分屏]
   ├── 左（.auth-aside · 品牌侧）
   │     1. 主标题：认识病害，从一张照片开始
   │     2. 三条价值点（.auth-points，每条 20px 描边图标 + 一句人话）
   │     3. 例图（.auth-aside-figure：真实病叶示例图，非抽象图）
   └── 右（.auth-card · 表单侧）
         4. 分段切换 .tabs（登录 / 注册）
         5. 表单 .form
              - 登录态字段：用户名、密码、[登录]主按钮
              - 注册态字段：用户名、显示名称(可选)、密码、[创建账号]主按钮
         6. 行内提示区（.alert：错误 / 成功）
         7. 演示账号提示条 .demo-hint（含「一键填入」）
[页脚 footer]
```

**首屏必须看到**：品牌、主标题、**两个输入框 + 主按钮 + 演示账号一键填入**（四要素一屏内可见，不需滚动）。

**栅格与断点行为**

| 断点 | 行为 |
|---|---|
| ≥1024 | 左右分屏 `1.05fr / 1fr`，左栏垂直居中；表单卡片内宽 ≤420px |
| 768–1023 | 单列；**隐藏左栏例图**（保留标题与价值点），表单居中 |
| <768 | 单列；表单卡片 padding 收到 `--space-5`；输入框与按钮均 `width:100%` |

**状态**

| 状态 | 呈现 |
|---|---|
| 默认 | 停在「登录」分段；用户名输入框自动聚焦 |
| 提交中 | 主按钮 `aria-busy="true"` + 内嵌 `.spinner`，文案改为「正在登录…」，两个输入框 `disabled`，按钮 `disabled` |
| 字段错误 | 对应字段 `.input[aria-invalid="true"]` + 下方 `.field-error`（16px 图标 + 文案）；**错误紧贴字段，不只在页面顶部** |
| 表单级错误 | `.alert.alert-error`（如「用户名或密码错误，请再试一次」） |
| 成功 | `.alert.alert-success`（「登录成功，正在进入…」）→ 300ms 后跳转 |
| 演示账号一键填入 | 点击后自动填 `demo` / `demo1234` 并聚焦主按钮 |

**空状态**：本页不适用（表单页无列表）。
**加载态**：即上表「提交中」。
**错误态**：区分「网络/服务错误」（「暂时连不上服务，请确认服务已启动后重试」）与「凭据错误」（「用户名或密码错误」——按 AC-04，**不得区分二者**）。

### 2.2 `cases.html` — 病害病例库

- **路由**：`/static/cases.html`
- **作用**：浏览 14 种作物 / 38 个类别的真实例图与简介；点击进入详情。
- **依赖 API**：`GET /api/v1/cases`

**信息架构**

```
[顶部导航 .site-nav]
[.page-head]  主标题「病害病例库」 / 副标题（说明可浏览规模）
[.filter-bar]  搜索框（按病害名过滤） | 作物下拉 .select（与左栏联动） | 计数「共 N 个类别」
[.cases-layout]
   ├── 左（.crop-list 粘性） 作物条目 × 14（名称 + 类别数），「全部作物」置顶
   └── 右（.case-grid） 病害卡片 × N
          └── .case-card：例图 / 病害中文名 / 作物名 / 简介(2 行截断)
[footer]
```

**首屏必须看到**：作物分类列表 + **至少 3 张带真实例图的病害卡片**（判据：进入页面第一屏就有图片，不是标题墙）。

**栅格与断点行为**

| 断点 | 行为 |
|---|---|
| ≥1024 | `[var(--case-side)=260px] [1fr]`；卡片 3 列；左栏 `position: sticky`（`top: calc(64px + var(--space-4))`） |
| 768–1023 | `[200px] [1fr]`；卡片 2 列；左栏仍粘性 |
| <768 | 单列；左栏降级为**横向可滑 chip 行**（`overflow-x:auto`，隐藏计数）；卡片 1 列；`sticky` 取消 |

**状态**

| 状态 | 呈现 |
|---|---|
| 加载 | 左栏 5 条 `.skeleton--line`；右栏 6 张 `.skeleton--card`（保持与真实卡片同尺寸，**CLS ≈ 0**） |
| 空（筛选无结果） | `.empty`：图标 `search` 24px + 标题「没找到相关病害」+ 文案 + 「清空筛选」次按钮 |
| 空（接口返回 0 作物） | `.empty`：图标 `bookOpen` + 「病例库暂时是空的」+ 「重试」 |
| 错误 | `.empty` 或 `.alert.alert-error`：「病例库加载失败，请确认服务已启动」+ 「重试」按钮 |
| 有数据 | `.case-grid` 正常渲染 |
| 边界 | 健康类别（`is_healthy=true`）卡片：不加"病害"语义色，名称旁加 `.pill.pill-success`（复用既有 pill），例图正常展示 |

**分页**：38 张卡片一屏可加载完，**不做分页**；仅在筛选结果 > 24 时启用「加载更多」（见 §3.11）。


**首屏必须看到**：例图 + 病害中文名 + 简介起始句（图文同屏，禁止"只有标题的首屏"）。

**栅格与断点行为**

| 断点 | 行为 |
|---|---|
| ≥768 | `.case-hero` 两栏 `1.1fr / 1fr`，图左文右 |
| <768 | 单栏；图在上、文在下；主按钮 `width:100%` |

**状态**

| 状态 | 呈现 |
|---|---|

| 错误（id 缺失/非法/404） | `.empty`：图标 `imageOff` + 「找不到这个病例」+ 「它可能已被移除，或链接不完整」+ 「返回病例库」主按钮 |

| 边界 | 长病害名换行不溢出（`word-break` 交给默认 + 容器不设固定高） |

### 2.4 `history.html` — 诊断历史

- **路由**：`/static/history.html`（**受保护页**）
- **依赖 API**：`GET /api/v1/history?limit&offset&crop&q`、`GET /api/v1/history/{id}`、`GET /api/v1/history/{id}/thumb?kind=`、`DELETE /api/v1/history/{id}`

**信息架构**

```
[顶部导航]  （认证区显示用户名 + 登出）
[.page-head] 「我的诊断记录」 / 副标题「登录后每次诊断都会自动存这里」
[.filter-bar]  作物下拉 .select（选项来自 meta） | 搜索框 | 「清除」ghost 按钮 | 计数「共 N 条」
[.rec-list]  .rec-row × N
   └── 缩略图(64) | 主信息(作物·病害 + 时间/严重度/可信度) | 可信度与严重度 pills | 操作(查看/删除)
[.load-more]  「加载更多」（offset 分页）
[详情弹层 .dialog-backdrop > .dialog]  例图/热力图切换 + 结论 + 处方
[删除确认弹层]  「确定删除这条记录？」[取消][删除]
[.toast-region]
[底部标签栏 .tabbar]（<768）
```

**首屏必须看到**：筛选栏 + 至少 2 条真实记录行（含缩略图），**不是空描述页**。

**栅格与断点行为**

| 断点 | 行为 |
|---|---|

| 状态 | 呈现 |

## 6. 给前端工程师的实现提示（不要漏）

1. **导航统一注入**：新增 `frontend/layout.js`，在每页 `<body>` 顶部注入 `.site-nav` 与移动端 `.tabbar`；`index.html` 现有的裸 `.topbar` 应被替换（同一套导航，避免两套并存）。当前页高亮用 `aria-current="page"`。
2. **样式合并**：把 `docs/design/功能扩展-新增样式片段.css` **整段**插入 `frontend/styles.css` 的「页脚」一节之后、「响应式」一节之前（片段自带 @media，不要重复改既有响应式段）。新增的 `:root` Token 一并并入。
3. **不硬编码**：作物下拉选项来自 `GET /api/v1/meta` 的 `supported_crops`；病例库数据来自 `/api/v1/cases`；严重度/可信度 pill 复用既有 `app.js` 的 `severityPill`/`confidencePill` 逻辑，**不要另写一套阈值**。
4. **受保护页**：`history.html` 先请求 `/api/v1/auth/me`；401 时跳 `login.html?next=history.html`；**先判定再渲染**，避免先闪空列表。
5. **未登录诊断**：诊断页带 token 时自动入库，不带则正常出结果、只弹一次 `toast-info`「本次结果未保存，登录后会自动留存」——**不阻断、不报错**（AC-10）。
6. **语音**：`index.html` 只加一个朗读按钮 + 少量 JS；文案拼装顺序固定；任何不可用路径都要有可见提示（AC-14/AC-15），并在重新诊断时 `cancel()` 复位。
7. **无障碍清单**：弹层 `role="dialog"`+`aria-modal`+`aria-labelledby`+focus trap+ESC+焦点归还；所有图标按钮 `aria-label`；错误字段 `aria-invalid`+`aria-describedby`；两处 live region（status / alert toast）；触控目标 ≥44px。
8. **反 AI 模板自查**（提交前逐条对照）：无 emoji 图标；无紫色→粉色渐变；无「Welcome to / Lorem ipsum」；无硬编码色值（除 `#fff`/`#000`）；无弹跳缓动；卡片无左侧色条；首屏是真实内容而非口号。
