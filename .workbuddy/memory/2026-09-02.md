## 方案 A：前景掩膜约束 Grad-CAM 热力图（执行完成）

### 背景
纯白背景 / 地板砖缝在 Grad-CAM 热力图里被当成病灶高亮。原因：
- Grad-CAM 是整图计算，无前景/背景概念；
- 训练集里大量病害本身是白色（白粉病/早疫病霉层等），模型学到了"白色≈病灶"捷径；
- 前置校验只拦背景，没有把背景从热力图中剔除。

### 改动
1. `backend/app/precheck.py`：新增 `leaf_foreground_mask(img)` 导出函数。
   - 绿色 HSV 掩膜 → 形态学闭/开运算 → 按连通域面积过滤 → drawContours FILLED（关键：把叶片内被病斑"挖空"的洞补进前景，病斑多为褐/黑/黄/白，不在绿色范围）→ 膨胀收边。
   - 不用凸包，避免把叶缘凹陷处的背景误包进来。
   - 参数：`FG_MORPH_KERNEL=7`、`FG_MIN_AREA_RATIO=0.004`、`FG_DILATE_ITERS=2`。
2. `backend/app/gradcam.py`：热力图叠加链路加前景约束。
   - `cam *= fg_mask / 255`（背景响应归零）；
   - `overlay = overlay*fg3 + img*(1-fg3)`（背景像素覆盖回原图，不涂热力色）。

### 验证
- `py_compile` 通过。
- `leaf_foreground_mask` 内存直比：背景像素差 = 0（完全还原）。
- 端到端 `/predict` 调用 demo 合规图返回 200，heatmap_url 生成成功。
- 视觉对比原图 vs 新热力图：纯白背景保持纯白未被涂色，叶片内病斑/褐区正常高亮。

### 注意事项 / 后续
- 用户实际体验后可能还需要：
  - 调 `FG_DILATE_ITERS`（叶缘病灶被裁时可加大）；
  - 如果绿色病害（黄叶/全黄）遇到掩膜漏抓，需在 `precheck` 同步校验。

   - `color = (fg>0) & (cam > 0.25)`，只对前景内高热力像素涂色，其余保持原图；
   - 这样凸包误包的背景（低热力）不会被涂成颜色，健康区也保持原图。

## 方案 C：Grad-CAM++ + 640 高分辨率 + Otsu 自适应阈值（执行完成）

### 背景
方案 A 落地后用户反馈：「病灶显示还算完整，但准确度不高。叶子中间偏左一片病灶，中间和左下也有两片都没被识别到。」

根因（三层叠加）：
1. **特征图分辨率太低**：YOLO11n-cls 目标层 C2PSA 在 224 输入下只有 7×7（640 输入 20×20），每个特征点对应原图约 32×32 像素，**比一片小病灶还大**，相邻病灶在特征图上压到同一个点，热力互相抵消或被其中一片稀释。
2. **标准 Grad-CAM 全局平均梯度**：`w^k = mean(grad^k)`，多病灶/重叠病灶中显著的那片会压制其它病灶。
3. **硬阈值一刀切**：`_HEAT_THRESHOLD=0.25` 在某些图偏高（漏弱病灶）、某些图偏低（涂健康区）。

### 改动
1. **`backend/app/gradcam.py` 完全重写**：
   - `_IMGSZ = 224 → 640`：目标层特征图 7×7 → 20×20，空间精度提升约 8 倍。
   - **Grad-CAM → Grad-CAM++**：
     - 标准：`w^k = mean(grad^k)`
     - Grad-CAM++：`alpha^k_ij = g² / (2g² + Σ A·g³)`，`w^k = Σ α·ReLU(g)`
     - 每个像素独立权重，弱但真实的病灶不会被强病灶的全局梯度稀释。
   - **Otsu 自适应阈值**：叶片前景内取热力值，做 64 bin Otsu 自动找「病灶高亮/健康低亮」最优分界；保护区间 `[0.12, 0.50]`。
   - 保留前景掩膜约束（凸包），不引入 GrabCut（避免再次切掉叶缘病灶）。
   - resize 用 INTER_CUBIC，热力边缘更平滑。
2. **不动部分**：
   - `detector.detect` 仍用模型训练尺寸 224（不影响分类准确度）；
   - `precheck.leaf_foreground_mask` 保持凸包填充逻辑。

### 验证
- `py_compile` 通过。
- 模型结构探查：目标层 9=C2PSA(256通道)，head=Classify(linear 38×1280)。224→448→640 输入下目标层特征图分别为 7×7 / 14×14 / 20×20。
- 单张热力图生成耗时 0.10s，前端体验无影响。
- 端到端 `/predict` 用用户实拍图（草莓·叶焦病, conf 0.9957, ood 0.2583 警告区间）：
  - 新热力图**清晰高亮**了「中间偏左」「中间/左下」两片病灶，叶缘焦枯多处高亮，白瓷砖背景完全干净。
  - 旧热力图（方案 A）弥散青绿色，看不出具体病灶位置。
- 5/5 回归测试全过（`scripts/verify_pipeline.py`）。
- 服务重启：旧 PID 25768 已 stop，新后台任务 `j39lJR`。

### 用户反馈通路
- 用户体验后若觉得还不够精细：可走方案 D（PlantVillage leaf segmentation 重训分割分支）；
- 或微调 `gradcam.py` 的 `_THRESHOLD_MIN`/`_THRESHOLD_MAX` 边界，或 `_IMGSZ` 进一步提升。

## 方案 F：色温异常检测通道（执行完成）

### 背景
方案 C 落地后用户反馈更尖锐，给出截图：黄笔圈出叶片顶部大片**深褐色/黑色坏死区** + 中间偏左**暗绿色/青绿色变色区**——这些"末期严重变色区"明显是病灶，但热力图完全没标。

### 根因（Grad-CAM 类方法的本质局限）
- Grad-CAM 高亮的是「对分类决定最关键的特征」，不是「所有真实病灶」；
- 末期大面积坏死/全黑/腐烂对类别判别贡献低（病程末期视觉上对所有同类都长一样），模型不依赖，热力趋近 0；
- 训练样本病程阶段不均衡（早/中期多，末期少）；
- 类激活空间稀疏性，对弥散/大块/低对比的末期变色不友好。

### 改动（`backend/app/gradcam.py`）
1. **新增 `_color_anomaly_mask(img, fg_mask)`**：在叶片前景内，统计健康绿色像素（HSV 范围与 precheck 一致：`H=[25,100], S=[40,255], V=[40,255]`）的 HSV 均值 `mu` 与协方差 `cov`；用 Mahalanobis 距离 `d = sqrt((x-mu)ᵀ cov⁻¹ (x-mu))` 度量每像素偏离健康叶色的程度；`d > 3σ`（`_ANOMALY_SIGMA=3.0`）判为色温异常；形态学 OPEN(3×3) + CLOSE(7×7) 去噪。
2. **健康像素下限保护**：`_ANOMALY_MIN_HEALTHY=200`，少于则统计不可靠、不启用色温通道（避免全叶病变时误判）。
3. **可视化叠加**：合成顺序「色温异常(底层品红) → 热力(覆盖)」。品红 BGR `(255,0,255)` 与 JET 红黄区分。
4. **保留 Grad-CAM++ 主体**：不动方案 C 的代码，仅在最终合成处叠加色温层。
5. **总开关**：`_ENABLE_COLOR_ANOMALY=True`，可快速关闭对比。

### 验证
- `py_compile` 通过。
- 自测：用户实拍图色温异常覆盖率 6.3%（前景 19.1%），异常像素 9340，纵向分布对上中下=1298/7482/560，集中在中上部（对应用户截图的坏死/变色区）。
- 单张热力图生成耗时 0.10s，与方案 C 持平。
- 端到端 `/predict` 用户实拍图：返回 200，top1=草莓·叶焦病 conf=0.9957 ood=0.2583。
- 视觉对比：新品红色**精准标出**用户圈出的边缘焦枯区，红黄热力保留在内部病斑区，健康叶原色，白瓷砖背景完全干净。
- 5/5 回归测试全过（`scripts/verify_pipeline.py`）。
- 服务重启：旧 PID 13764 已 stop，新后台任务 `Gh1Tg3`。

### 用户反馈通路
- 用户体验后：
  - 色温误标多（老叶/阴影）→ `_ANOMALY_SIGMA` 升到 4.0；
  - 色温漏检 → `_ANOMALY_SIGMA` 降到 2.5，或扩展 `_HEALTHY_H/S/V` 范围；
  - 仍漏大块严重变色 → 走方案 E（独立分割模型重训，从根上解决「分类关键 ≠ 病灶」问题）。

## 方案 F v2：品红改暖色 + 白色背景抑制（2026-09-02 晚）

**用户反馈**：
1. 品红范围超出，标记了背景白色部分；
2. 视觉上希望保持「冷→暖」的单一过渡，不希望出现品红色。

**改动**：
1. `gradcam.py` 常量：删除 `_MAGENTA`，新增：
   - `_ANOMALY_HEAT=0.85`（异常区在 JET 中的热力值，暖色端）；
   - `_WHITE_S_MAX=30` / `_WHITE_V_MIN=180`（白色背景/高光抑制阈值）。
2. `_color_anomaly_mask`：
   - 加全图 `white_mask = (S<_WHITE_S_MAX) & (V>_WHITE_V_MIN)`；
   - 前景内异常判定时排除 white；
   - 形态学闭运算之后再用全图 `white_mask` 清除一次，避免闭运算把白色背景扩散进 anomaly。
3. `generate_cam` 合成逻辑（核心调整）：
   - 删掉品红标注的「anom_blend」叠加；
   - 改为：异常区 `cam = max(cam, anom_f * 0.85)`，抬升到 JET 暖色端；
   - 重新算 Otsu 阈值，异常区因 cam=0.85 > 阈值上限 0.50 自动涂色；
   - 输出图统一走 JET 冷→暖，无新颜色。

- `py_compile` 通过。
- 自测：用户实拍图品红像素 = 0（v1 大量误标），暖色像素 = 17110。
